# Календарь звонков


[![hexlet-check](https://github.com/EMIR1HUB/ai-for-developers-project-386/actions/workflows/hexlet-check.yml/badge.svg)](https://github.com/EMIR1HUB/ai-for-developers-project-386/actions)

Разработайте совместно с ИИ сервис для бронирования календаря

Учебный проект Хекслета: https://ru.hexlet.io/programs/ai-for-developers
Как это должно работать: https://files.hexlet.app/a/2ipc5m

## Сценарий

Две роли: **владелец** (один, задан заранее, без авторизации) и **гость** (без регистрации).

### 1. Владелец создаёт тип встречи
1. Открывает «Админка» → «Типы встреч» и нажимает «Создать».
2. Заполняет название («Встреча 15 минут»), описание и длительность (15 мин), сохраняет.
3. Тип появляется в списке в админке и на публичной странице «Записаться».

### 2. Гость записывается на звонок
1. На главной нажимает «Записаться».
2. Видит карточку владельца и список типов встреч (название, описание, длительность) и выбирает тип.
3. Открывается календарь на ближайшие 14 дней. Дни вне окна недоступны, у остальных дней показано число свободных слотов.
4. Выбирает дату. Справа появляется список слотов длительностью выбранного типа со статусом «Свободно» или «Занято».
5. Выбирает свободный слот и нажимает «Продолжить».
6. Вводит имя, email и, по желанию, заметку, затем подтверждает бронь.
7. Видит подтверждение: тип встречи, дата и время. Если слот успели занять, гость получает ошибку и возвращается к выбору времени.

### 3. Владелец видит запись
1. Открывает «Админка» → «Предстоящие встречи».
2. Видит новую запись: тип, дату и время, имя и email гостя, заметку. В списке встречи всех типов, отсортированные по времени начала.

## Требования

### Обязательные функции
- Владелец: создание и просмотр типов встреч (название, описание, длительность), список предстоящих встреч всех типов.
- Гость: список типов встреч, календарь доступности на 14 дней, бронирование свободного слота.

### Правила бронирования
- Окно записи: 14 календарных дней, сдвигается со временем. В спецификации фиксируются: начинается окно сегодня или завтра, рабочие часы, часовой пояс и шаг стартов слотов.
- Длительность слота равна длительности типа встречи.
- Пересечения запрещены, в том числе частичные и между разными типами. Встреча может начинаться ровно в момент окончания предыдущей (интервал `[start, end)`).
- Правила действуют и для одновременных запросов: из двух конкурирующих броней одного времени проходит одна, вторая получает конфликт.

### Ограничения
- Один владелец, задан заранее. Нет авторизации, личных кабинетов, внешних календарей и уведомлений.
- Данные хранятся в памяти процесса или в БД, выбор фиксируется в спецификации. Если хранение в памяти, перезапуск сбрасывает записи, и это нужно указать здесь.
- Приложение собирается в Docker-образ и запускается в контейнере.

### API и генерация кода
- Контракт описан на TypeSpec. Из него генерируется OpenAPI-спецификация, а из неё клиентский SDK для фронтенда.
- До выбора стека нужно проверить, что для языка фронтенда есть генератор клиента из OpenAPI.
- Серверные типы и маршруты генерируются, если фреймворк это поддерживает. Если нет, бэкенд пишется по контракту и проверяется тестами.
